# 20260901 Strong-teacher mixed 10k-game retraining

Status: complete

## Idea

Build a reproducible library of 10,000 7x7 games with rich moves from the
requested native Pathfinder teacher (depth 5, beam 256, 500,000 nodes), then
make a clean replay-training pass across the available learner families. The
final mix is 8,000 games against the strong d5/b256/500k search opponent and
2,000 against a weaker d3/b64/12k opponent. The teacher stays the Rust rules
and search authority; Python is used only to orchestrate replay learners and
analyze their checkpoints.

## Starting point

The current supported Pathfinder work has a larger research history, but no
10k-game archive generated by the exact d5/b256/500k envelope. The existing
schema-v2 replay contract already records every selected action, search
telemetry, outcome, and agent specification. The existing Python lab exposes
GNN policy/value, fixed-board CNN policy/value, and Q/Advantage GNN learners.

## Protocol

The generation runner shards disjoint seed ranges and invokes the release Rust
self-play binary with the d5/b256/500k teacher as the candidate in both source
pools. A small seeded opening-randomness window creates diverse roots; all
subsequent teacher decisions use the requested envelope. The strong pool uses
d5/b256/500k replies; the variety pool uses d3/b64/12k replies. Raw JSONL and
logs remain in this path's ignored `workspace/`. The audit checks schema,
provenance, seed uniqueness, action legality, replayed winners, move
telemetry, duplicate sequences across both pools, opponent-profile coverage,
and source-disjoint train/heldout splits. The compact content-addressed
result is promoted under `data/corpora/` only after all gates pass.

The retraining runner uses the frozen game split and trains GNN policy/value,
CNN policy/value, and Q/Advantage GNN checkpoints with symmetry augmentation.
Because the native teacher archive contains the selected action and scalar
search telemetry rather than a complete root-Q vector, the Q/Advantage pass is
an outcome/policy replay fit; it is not reported as full root-Q supervision.

## What happened

An initial 40-ply schedule was measured and stopped before any shard
completed: the exact d5/b256/500k budget projected a multi-day local run. Its
zero-byte shard files are retained only as evidence of the failed schedule;
none are part of the corpus. The active schedule uses the 20-ply cap described
above.

During the mixed-plan adjustment, one weak-pool launch was also discarded
before completion: its seed range overlapped the reserved strong top-up range,
and the first command-builder revision still hardcoded the opponent flags. Its
zero-byte outputs remain isolated in the workspace as failure evidence. The
corrected rerun uses the disjoint `2026110100` seed range and records the weak
d3/b64/12k profile explicitly.

The practical generation cap is 20 plies: four seeded random opening plies
followed by 16 native teacher decisions. This is a deliberate policy-replay
corpus rather than a finished-game strength league; all generated records are
still valid capped games, and the cap is retained in provenance. The strong
source pool produced 8,000 records with 7,998 unique action sequences, so a
100-game d5/b256/500k top-up was generated. The weak source pool produced
2,100 records with 2,099 unique action sequences. The final selection contains
8,000 strong-profile games and 2,000 weak-profile games; the mixed audit
passed with 10,000 unique full action sequences and no duplicate seeds. No
production opponent or browser default is changed by this experiment.

## Data and artifacts

Disposable raw games, split archives, checkpoints, reports, and logs belong in
the ignored `workspace/`. The reusable compact mixed game library is promoted
under `data/corpora/teacher-d5-b256-500k-v1/`. The final 5,000-step replay
pass produced GNN policy/value, CNN policy/value, and GNN Q/Advantage
checkpoints under `workspace/retraining-mixed-final/`. The Q/Advantage learner
has `qTargetPositions: 0` because the native records contain selected actions
and scalar search telemetry, not complete root-Q vectors; it is an
outcome/policy replay fit rather than full Q supervision.

## Project impact

This path is intended to provide a materially larger, source-disjoint replay
corpus for the existing learner architectures while preserving the current
v4/default and its rollback controls.

## Next decision

Held-out replay metrics were collected for all three learners. This pass does
not promote a model: no arena/legality gate was run against the production
default, so the existing v4/default and rollback controls remain unchanged.
The corpus, provenance, audits, and checkpoints are retained for the next
explicit learner-strength evaluation.
